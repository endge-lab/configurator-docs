# Cookbook

Cookbook собирает законченные пользовательские сценарии, которые проходят
через несколько документов Endge. В отличие от справочника API, каждый рецепт
начинается с ожидаемого поведения и показывает, какие сущности создать в
Configurator и как связать их в Composition.

## Данные и синхронизация

- [Оптимистичные обновления](/cookbook/optimistic-updates) — сразу показать
  локальное изменение, пометить его через Raph Meta, отправить Query и снять
  ожидание после следующего серверного события.

## Как читать рецепты

Имена документов, путей Store и namespaces в примерах условны. Заменяйте их на
свои identities, сохраняя распределение ответственности:

- Action оркестрирует последовательность шагов;
- Query выполняет сетевой запрос;
- Store-owned Update изменяет Data и Meta;
- Stream доставляет нормализованное серверное событие;
- Composition связывает runtime-узлы и данные;
- Component SFC только отображает состояние и запускает Action.

Точные контракты каждой сущности остаются в разделе Core. Cookbook не вводит
отдельный runtime API или скрытую автоматику поверх этих контрактов.
