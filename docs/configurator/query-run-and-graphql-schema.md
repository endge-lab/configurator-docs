# Запуск Query и схема GraphQL

Редактор Query позволяет выполнить запрос с заданными props и посмотреть ответ,
не создавая Composition. Для GraphQL Query и Stream с `graphqlSse(...)` редактор
загружает схему GraphQL: по ней проверяется документ внутри `gql` и работает
автодополнение.

## Панель запуска Query

Кнопка ▶ на панели инструментов редактора Query открывает и закрывает панель
«Запуск Query». Запрос не отправляется сразу: сначала можно заполнить props.
Панель открывается поверх любой вкладки редактора и показывает бейдж REST или
GraphQL.

1. Заполните props. Поле создаётся для каждого prop из `defineProps` текущего
   текста Source, сохранять документ не нужно. Пустое поле означает значение по
   умолчанию: prop не передаётся, и runtime применяет default. Boolean выбирается
   из «По умолчанию / true / false», объекты, массивы и Type вводятся как JSON.
2. Для GraphQL проверьте блок «Итоговые variables»: он пересчитывается при
   вводе из default, значений формы и переменных Workspace.
3. Нажмите «Выполнить» или `Ctrl/Cmd+Enter`.

Если каждый prop необязателен или имеет default, рядом с ▶ появляется кнопка
«Запустить»: она открывает панель и сразу выполняет Query.

Панель и другие предпросмотры компилируют Source в контексте текущего запуска
(`Endge.source.currentSourceContext()`): `contextSwitch`, `facet` и `config`
дают значения выбранного тенанта.

Ошибка ввода или компиляции Source показывается в панели, кнопка запуска при
этом неактивна. Запуск выполняется штатным runtime Query: те же AuthProfile,
переменные Workspace, mock, outputs и DataView, что и в приложении. Текст
редактора записывается в Query домена без сохранения документа.

После запуска панель показывает «Успешно» или «Ошибка», HTTP-статус и
длительность. Ошибка выводится с классом: «Ошибка GraphQL», «Ошибка транспорта»,
«Некорректный ответ GraphQL», «Ошибка подготовки» или «Ошибка выполнения».

| Вкладка | Содержимое |
| --- | --- |
| Ответ | Сырой HTTP-ответ, в том числе тело ответа с кодом 4xx/5xx |
| Запрос | Метод, URL, заголовки, параметры URL; для GraphQL — variables и документ, для REST — тело |
| Ошибки GraphQL | `message`, `path`, `locations`, `extensions` каждого элемента `errors`; видны при любом `errorPolicy` |
| Outputs | Значения outputs Query после запуска |

Если ответ содержит GraphQL errors, после запуска открывается вкладка «Ошибки
GraphQL», иначе — «Ответ».

Во вкладке «Запрос» скрываются значения заголовков и параметров, заполненных
AuthProfile, а также заголовков и параметров с именами вида `Authorization`,
`Cookie`, `token`, `api-key`, `secret`, `password`, `session`, `signature`,
`csrf`/`xsrf`, `jwt` и userinfo в URL. Строка «Скрыто: …» перечисляет скрытые
имена. Тело запроса (GraphQL `{ query, variables }`, JSON REST, строка с JSON) и
variables маскируются рекурсивно по тем же секретоподобным ключам, включая
camelCase (`clientSecret`, `userPassword`, `apiKey`): значение заменяется на
`***`, путь (`variables.password`) попадает в «Скрыто: …». Неструктурированный
текст тела не маскируется.

Если Query выполнен на mock-данных или в режиме mock, HTTP-запрос не
отправляется, и панель сообщает об этом.

## Схема GraphQL

Кнопка «Схема GraphQL» находится справа на панели вкладки Source у GraphQL Query
(`kind: 'graphql'`) и у Stream. Для Stream меню доступно, только когда transport —
`graphqlSse(...)`. Точка на кнопке означает, что схема загружена.

| Действие | Назначение |
| --- | --- |
| Загрузить схему с endpoint | Introspection-запрос на endpoint документа с его headers, auth и timeout |
| Загрузить схему из файла… | SDL (`.graphql`, `.gql`, `.graphqls`) или JSON introspection, если introspection на сервере выключен |
| Импортировать типы из схемы | Открывает диалог [импорта Type](/reference/type#импорт-из-graphql) с планом из сохранённой схемы |
| Удалить сохранённую схему | Удаляет схему этого endpoint |

Endpoint, заданный через `prop(...)`, не позволяет привязать схему: меню сообщает
«Endpoint вычисляется из props». Схема хранится в IndexedDB браузера по backend,
Workspace и разрешённому endpoint, поэтому `env(...)` разных сред даёт разные
записи. Если браузер не сохранил схему, она доступна до перезагрузки страницы.
Выход из Configurator удаляет сохранённые схемы.

Stream `graphqlSse` получает introspection обычным POST-запросом на свой URL.
Если сервер graphql-sse не отвечает на такой запрос, загрузите схему из файла.

### Проверка и автодополнение

При загруженной схеме ошибки документа внутри `gql` подчёркиваются на месте:
неизвестное поле, неизвестный аргумент, несовместимый тип переменной,
синтаксис. Такие маркеры имеют источник «GraphQL schema» и показываются вместе с
диагностиками компилятора. Те же проблемы с префиксом «GraphQL schema: »
показывает вкладка «Диагностика» редактора Query и Stream (вычисляются при
открытии вкладки). В общий список Problems они не попадают: компиляция
выполняется без сети и без схемы. У Query с `fragments` по контексту по схеме
проверяется каждый вариант document. У Stream с `url` из props схема к адресу не
привязывается.

Внутри `gql` автодополнение предлагает виды operation, поля текущего типа с
типом и описанием, аргументы поля, поля input-объектов, значения enum,
объявленные `$переменные`, input-типы в объявлениях переменных, типы после
`... on` и `fragment X on` и директивы после `@`. Подсказки Source DSL внутри
`gql` не показываются. Проверка и автодополнение работают для tagged template
`` gql`...` `` без `${}`; вызов `gql('...')` не поддерживается.
