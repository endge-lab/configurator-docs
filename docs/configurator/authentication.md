# Аутентификация

Аутентификация устанавливает identity запроса, авторизация — доступные действия. Вход через OIDC не означает автоматическое управление ролями: backend поддерживает локальные назначения и внешний маппинг claims.

## Способы входа

| Способ | Назначение |
| --- | --- |
| [OIDC](./authentication/oidc) | Интерактивный вход через совместимого provider, cookie session и refresh |
| [Dev identity](./authentication/development) | Фиксированная identity для изолированной разработки |
| [Персональный токен](/agents/tokens) | Ограниченный доступ агента через backend API/MCP |

Настройки входа принадлежат Service Backend. Документы [AuthProfile](/reference/auth-profile) в Workspace настраивают запросы конечного runtime и не определяют административные права Configurator.

## Bearer JWT для API {#backend-bearer}

В OIDC-режиме backend принимает проверяемый JWT:

```http
Authorization: Bearer <access_token>
```

Проверяются signature, issuer, audience и срок действия согласно [OIDC-настройкам](./authentication/oidc#проверка-токена-и-обновление-сессии). Произвольный opaque token или Basic Auth не заменяет этот механизм. Персональные токены Endge имеют собственный контракт, ограничения и lifecycle.

## Роли

| Область | Роль | Назначение |
| --- | --- | --- |
| Платформа | Admin | Администрирование платформы и доступ ко всем Workspace |
| Workspace | Admin | Администрирование выбранного Workspace |
| Workspace | Editor | Чтение и изменение документов |
| Workspace | Viewer | Чтение документов |

Platform Admin не ограничивается более слабым назначением в одном Workspace. Конкретная операция дополнительно проверяет свой permission и, для персонального токена, его scopes.

## Источник назначений

| | `local` | `external` |
| --- | --- | --- |
| Управление | Администратор Endge | OIDC claims и файл маппинга |
| БД | Локальные назначения | Производный снимок внешних назначений |
| Ручные mutations доступа | С проверкой административной роли | `403 access_managed_externally` |
| Обновление | При изменении администратором | После проверки текущего токена и синхронизации |

Режим выбирается при запуске backend. [Файл внешних прав](./authentication/access-configuration) уже реализован в backend. Отдельный read-only экран «Мои права» в текущем UI Configurator не реализован: не используйте его как обязательный шаг настройки. Backend остаётся источником решений о доступе независимо от состояния кнопок UI.

В local-режиме bootstrap первого активного пользователя и `AUTH_PLATFORM_ADMIN_SUBJECTS` / `AUTH_PLATFORM_ADMIN_GROUPS` могут создать постоянное локальное назначение. Исчезновение группы из JWT не удаляет такое назначение автоматически. Во external-режиме локального fallback нет.

## Синхронизация и отзыв

Во external-режиме backend проверяет identity и token, вычисляет полный набор и атомарно заменяет назначения текущего пользователя. Пустой набор удаляет прежние права. Ошибка синхронизации не позволяет продолжить защищённый запрос со старым набором. Более старый `iat` не откатывает уже применённый снимок; конфликтующие токены с одинаковым `iat` диагностируются.

JWT действует до своего expiry; Endge не запрашивает текущие роли у provider на каждую проверку подписи. Новый токен после refresh приносит обновлённые claims. Старое назначение в БД само по себе не заменяет действующую аутентификацию. Настройте срок токена согласно допустимой задержке отзыва.

Прямые SAML/LDAP adapters для входа не реализованы; такие системы можно подключить за OIDC provider. Сырой JWT и секреты не должны попадать в public examples, журнал или Source.
