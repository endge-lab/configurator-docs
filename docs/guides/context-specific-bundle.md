# Сборка выбранного контекста

Для поставки одного варианта приложения выбирайте «Стартовая композиция и её зависимости». Этот режим является начальным для новых профилей сборки. Он начинает обход от `startupCompositionIdentity` workspace и сохраняет только транзитивные исполняемые зависимости выбранных веток.

## Поддержка в целевом контуре

Наличие этой страницы в общей документации не доказывает, что реализация уже поставлена в конкретный контур. Перед использованием проверьте фактически развёрнутые версии: backend через `GET /version`, Configurator — в его интерфейсе; маршрут к исходникам и версиям описан в [руководстве агента](/agents/repositories).

Для этого режима нужны Compiler `program-v5`, execution graph версии 1 и поддержка пары `startup-composition / effective-context` в Configurator и backend. Устаревший backend может отклонить новые настройки профиля; старый Bundle без execution graph нельзя превратить в изолированный Bundle без повторной компиляции. Версии в [contracts manifest](/contracts-manifest.json) описывают опубликованный snapshot документации и не заменяют проверку версии работающего сервиса.

Проверенный состав поставки этой возможности:

| Компонент | Версия |
| --- | --- |
| `@endge/core` | `1.1.0-dev.13` |
| `@endge/ui-vue` | `1.0.1-dev.12` |
| `@endge/computation-sandbox` | `1.0.1-dev.9` |
| Configurator | `2.14.0` |
| Service Backend | `0.18.0` |

UI Vue и sandbox в этой поставке поддерживают новую prerelease-линию Core. При встраивании Bundle в собственное приложение используйте совместимый host; наличие поддержки на сервере хранения не обновляет runtime на машине клиента.

## Выбор фасетов

Перед сборкой выберите значения всех необходимых фасетов в Configurator. При интеграции Core выбор передаётся в boot context:

```ts
await Endge.boot({ ...ctx, context: { facets: { tenant: 'variant-b' } } })
const sourceSnapshot = await Endge.buildSavedProgram()
const bundle = Endge.program.exportBundle({ scope: 'startup-composition' })
```

`buildSavedProgram` загружает сохранённое состояние и компилирует его без запуска Runtime. Bundle фиксирует фактический resolved context вместе с effective configuration. Несохранённые editor drafts в него не входят. Смена фасетов требует нового boot/build. Подробности: [выбор тенанта](/configurator/tenant-selection) и [контекст сборки](/reference/value-expressions#контекст-сборки).

## Стартовая Composition и вложенные ветки

Стартовая Composition выбирается ссылкой `startupCompositionIdentity` в workspace. Саму эту ссылку фасеты не переключают. Она может указывать на общий документ `app-entry`, внутри которого объявлен структурный выбор вложенных Composition.

Например, в модели существуют фасеты `tenant` и `channel`, документы фасетов `customer-a`, `customer-b`, `web`, `mobile` и указанные ниже исполняемые документы. Это пример identities, а не встроенные в Endge имена.

Source стартовой Composition `app-entry`:

```ts
defineComposition({
  runtimes: {
    application: contextSwitch({
      default: composition('application-default'),
      cases: [
        { when: { tenant: 'customer-a' }, use: composition('application-a') },
        { when: { tenant: 'customer-b' }, use: composition('application-b') },
      ],
    }),
  },
})
```

Source вложенной Composition `application-b`:

```ts
defineComposition({
  runtimes: {
    screen: contextSwitch({
      default: component('customer-b-web'),
      cases: [
        { when: { channel: 'mobile' }, use: component('customer-b-mobile') },
      ],
    }),
  },
})
```

Для выбора обеих осей перед компиляцией:

```ts
await Endge.boot({
  ...ctx,
  context: { facets: { tenant: 'customer-b', channel: 'mobile' } },
})
await Endge.buildSavedProgram()
const bundle = Endge.program.exportBundle({ scope: 'startup-composition' })
```

В Bundle останется `app-entry → application-b → customer-b-mobile` и необходимые этому графу зависимости. `application-a`, `application-default` и `customer-b-web` исключаются, если на них нет другой исполняемой ссылки из выбранного графа. Общий компонент или Query сохраняется, если выбранная ветка его использует.

Один `contextSwitch` выбирает одну ветку; несколько переключателей разрешаются независимо в одном контексте. Условие может включать несколько фасетов, например `when: { tenant: 'customer-b', channel: 'mobile' }`. Контекст не ограничивается фасетами: он также содержит effective configuration и другие параметры; здесь выбирающие условия проверяют именно фасеты.

Если подходят несколько cases, выбирается наиболее специфичный. Пересекающиеся cases одинаковой специфичности компилятор отклоняет: порядок строк не задаёт приоритет.

Все условия сохраняются в авторском Source и используются при компиляции. В scoped Bundle нет переключателя между заказчиками, ожидающего решения на машине клиента: выбор уже выполнен, невыбранные artifacts и описания альтернативных веток удалены. Чтобы получить другой вариант, требуется новая компиляция и экспорт. Изменение фасета после загрузки файла само по себе не восстанавливает отсутствующие документы.

Следует различать два этапа: текущий компилятор проверяет всю загруженную модель, а экспорт отбирает только выбранное замыкание. Отсутствие документа в поставляемом файле не означает, что его Source вообще не читался при проверке модели.

## Что включается

- Стартовая Composition, вложенные выбранные Composition и их зависимости: Component SFC, Query, Store, Stream, Update, Action, DataView, типы и ресурсы.
- Общие зависимости, на которые выбранный граф явно ссылается.
- Узлы с ручной активацией или динамическим `activateWhen`: они могут потребоваться при работе приложения.
- Выбранные варианты `contextSwitch`; узлы, исключённые структурным `enabledWhen`, не возвращаются при экспорте.
- Требования к используемым host Actions и теги включённых SFC.

Проверка компилятора по-прежнему рассматривает все варианты модели. Ссылки, нужные только для проверки невыбранных вариантов, помечены `validationOnly` и не участвуют в обходе экспортируемого графа. Ошибка полной компиляции блокирует экспорт.

## Что исключается

Невыбранные artifacts, неиспользуемые документы, полный каталог папок, описания альтернативных веток и compiler diagnostics не включаются. Каталог содержит только документы выбранных artifacts, без ссылок на исходную структуру папок. Authoring-модели Query и других неисполняемых Source-проекций не передаются. Нормализованный исполняемый документ Action сохраняется: он нужен его executor.

AST запрещён в этом режиме, включая запрос `includeAst: true`: он может содержать исходный текст остальных вариантов. Ошибку также вызывают отсутствие стартовой Composition, неполная/устаревшая программа, отсутствующая исполняемая зависимость и программа без нового execution dependency graph. Старые Bundle можно просматривать как раньше; для контекстного экспорта модель нужно пересобрать.

Обычные literals, metadata и effective configuration остаются данными выбранного приложения. Фасеты не классифицируют произвольный текст внутри общего документа. Если общий literal содержит данные нескольких заказчиков или выбранный граф явно ссылается на чужой документ, они не становятся закрытыми автоматически. Для разделения используйте структурный выбор веток и корректные configuration contributions. Runtime-условие видимости интерфейса не является границей изоляции экспортируемого файла.

## Сохранение в релиз

Configurator упаковывает результат в существующий контейнер `endge-bundle` и передаёт Gzip в `POST /api/v1/releases/from-build`. Metadata содержит `scope: 'startup-composition'`, `contextMode: 'effective-context'`, фактический context и source revision. Backend проверяет согласованность режима с Bundle, отсутствие AST в настройках и привязку к исходной ревизии; затем сохраняет snapshot и готовый бинарник в релиз. Повторно компилировать модель на backend не требуется.

Backend не доказывает семантическое соответствие загруженных artifacts исходникам и не выступает компилятором. Гарантия отбора относится к штатному экспорту Core, а не к произвольному файлу, сформированному сторонним клиентом.

У релиза два разных представления:

| Endpoint | Содержимое |
| --- | --- |
| `GET /api/v1/releases/{identity}/bundle` | Сохранённый compiled Bundle; для поставки выбранного контекста нужен файл с `exportScope: 'startup-composition'` |
| `GET /api/v1/releases/{identity}/export` | JSON snapshot исходной модели выбранного commit; это полный workspace, который может содержать документы других заказчиков |

Scoped Bundle не сужает исходный snapshot релиза, backup или `/api/v1/domain/export`. Для передачи одному заказчику нельзя подменять compiled Bundle этими полными экспортами. Это также не вводит tenant-level авторизацию на API workspace: права доступа к исходной модели остаются отдельным backend-контрактом.

## Полный экспорт для инспекции

«Вся модель — для инспекции» сохраняет прежний полный каталог и artifacts. Такой файл может содержать документы других контекстов и не подходит для изолированной поставки заказчику. Программный прежний вызов `Endge.program.exportBundle({ includeAst: true })` сохраняет эту семантику. Существующие сохранённые профили полной модели не переименовываются в контекстные автоматически.

Execution Bundle содержит программу для совместимого Endge host, а не самостоятельный системный executable. Host предоставляет renderer, транспорт, зарегистрированные code providers и другие внешние capabilities.
