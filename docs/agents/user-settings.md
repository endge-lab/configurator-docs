# Серверное хранение настроек пользователей

Подключайте transport в хосте и передавайте стабильный ID текущей учётной
записи. Для Configurator это ID пользователя Service Backend из сессии.
Другой потребитель может передать проверяемый access token через `getHeaders`.

```ts
import { createEndgeBackendWorkspaceStateTransport, Endge } from '@endge/core'

await Endge.boot({
  ...bootOptions,
  workspaceState: {
    account: () => currentSession()?.backendUserId ?? null,
    backend: createEndgeBackendWorkspaceStateTransport({
      baseUrl: serviceBackendUrl,
      getUserId: () => currentSession()?.backendUserId ?? null,
    }),
    backendKeys: ['configurator.date-format'],
  },
})
```

Core уже подключает `endge.ui.zoom`. Для дополнительного ключа добавьте
его определение и проверку значений в серверный каталог `user_state/catalog.go`.
Опишите его на русском и английском и добавьте ключ в `backendKeys` хоста.
Серверный каталог используется для проверки записи, справки и JSON Schema Monaco.
Потребитель хранит настройку под стабильным ключом через
[`Endge.context`](/advanced/context-state/dynamic-state).

## HTTP

Все запросы идут под `/api/v1/user-state` с `X-Endge-Workspace`. Query-параметр
`facets` содержит URL-encoded JSON объекта выбранных документов фасетов.
Cookie-запись требует разрешённый Origin. Персональные токены
`endge_pat_…` не дают доступа к пользовательским настройкам.

| Метод и путь | Результат |
| --- | --- |
| `GET /` | Свой снимок с `actorId`, `partition`, `resetRevision` и `entries` |
| `PATCH /` | Пакет своих операций с `actorId`, `partition` и `resetRevision` |
| `GET /admin/contexts` | Доступные контексты, разрешённый текущий контекст и каталог |
| `GET /admin/users` | Пользователи с записями, фильтр `q` и курсор `after` |
| `GET /admin/users/{user}` | Снимок указанного пользователя в разрешённом контексте |
| `PATCH /admin/users/{user}` | Изменения по ревизиям в выбранном контексте |
| `POST /admin/reset` | Сброс пользователя с `userId` и `confirmation: "reset-user"` или всех в контексте с `confirmation: "reset-all"`. Передайте `partition` из выбранного контекста |

Операция содержит `key`, UUID `id`, `baseRevision` и либо `value`, либо
`delete: true`. Для нового ключа используйте ревизию `0`. На пакет действует
лимит 32 операций и 64 КиБ. Ответ содержит результат по ключу
`saved`, `conflict` или `reset`. Повтор одного UUID обрабатывается безопасно.
Успешная часть пакета применяется даже при конфликте отдельного ключа.
Для разрешения конфликта используйте подтверждённую ревизию после осознанного
решения владельца настройки. Сброс инвалидирует прежнюю очередь через
`resetRevision`. Запись и сброс из панели журналируются с ID администратора,
контекстом и целью.

## Граница среды и фасетов

Backend выбирает среду из `ENDGE_USER_STATE_ENVIRONMENT`, по умолчанию из
`APP_ENV`. Назначьте разные ID окружениям, которые работают с одной БД.
Браузер присылает выбранные документы фасетов, а Backend проверяет их
принадлежность workspace и вычисляет итоговый драйвер по сохранённой
конфигурации. Записи всех пользователей ограничены одним полным контекстом.

Для фасета `tenant` и дополнительных фасетов из
`ENDGE_USER_STATE_PROTECTED_FACETS` требуется членство в группе проверенной
OIDC-сессии вида `/endge-user-state/<environment>/<workspace>/<facet>/<document>`.
Каждый сегмент пути кодируется отдельно. Правило действует при выдаче списка,
чтении, записи и сбросе, включая Workspace Admin и Platform Admin. Добавьте в
эту настройку любой фасет, разделяющий доступ к данным, прежде чем включать
для него серверное хранение. Обычные фасеты используют права рабочего
пространства.

Для проверки используйте отдельное рабочее пространство и тестовые записи.
Проверьте сохранение после перезагрузки, редактирование в Monaco, конфликт
одного ключа, изоляцию контекста и оба подтверждаемых сброса.
